# Phase 4.3: Promotion Scenario Engine & Optimization

## Objective
Build deterministic scenario comparison (Current vs Promo A vs Promo B vs Combo vs No Promo) and bounded optimization with explicit objectives and hard constraints.

## Must-Haves (Goal-Backward Verification)
- [ ] Scenario engine compares 5 scenarios with deterministic economics
- [ ] Promotion elasticity from historical data (discount → demand change, diminishing returns)
- [ ] Bounded discount search: ₹0, ₹10, ₹20, ₹30, ₹40, ₹50
- [ ] 7 explicit objectives: revenue_growth, profit_growth, aov_growth, footfall_growth, inventory_reduction, customer_retention, slow_hour_utilization
- [ ] Hard constraints: min margin, max discount, min price, inventory, eligibility, duration, rules
- [ ] Cannibalization model: incremental = total_expected - baseline_expected
- [ ] "No promotion" as first-class scenario

### Task 2: Create ElasticityService (Historical Learning)
**read_first:**
- backend/src/services/offerAnalyticsService.ts (getOfferPerformance)
- backend/src/models/OfferAnalytics.ts
- backend/src/models/Offer.ts

**action:**
Create `backend/src/services/elasticityService.ts`:
- `ElasticityService` class with method `estimateElasticity(restaurantId, branchId, productId): Promise<ElasticityPoint[]>`
- For each product, find historical OfferAnalytics where offer.applicableProductIds includes product
- For each offer, calculate: discount_level = offer.value (flat) or offer.value * avg_price / 100 (percentage), demand_delta_pct = (redemptions / baseline_demand - 1) * 100
- Baseline_demand = average daily sales of product in same period without offer
- Fit piecewise linear or logarithmic curve through (discount, demand_delta) points
- Detect diminishing returns: if slope decreases at higher discounts
- Store in PromotionElasticity collection
- Cache for 24 hours

### Task 3: Create ScenarioEngine
**read_first:**
- backend/src/services/forecastService.ts (ForecastEngine)
- backend/src/services/profitabilityService.ts (offerEconomics)
- backend/src/services/inventoryDemandService.ts (stockout risk)
- backend/src/services/offerEngine.ts (OfferSuggestion structure)

**action:**
Create `backend/src/services/scenarioEngine.ts`:
- `ScenarioEngine` class with method `compareScenarios(restaurantId, branchId, baseEntity, scenarios: ScenarioInput[]): Promise<PromotionScenario[]>`
- ScenarioInput: { type: 'promo'|'combo'|'no_promo', offer_config, target_products }
- For each scenario:
  1. Get baseline forecast (current demand from ForecastEngine)
  2. If promo: apply elasticity to get expected_demand = baseline * (1 + elasticity(discount))
  3. If combo: use attachment rates from computeAttachment + combo discount
  4. If no_promo: expected_demand = baseline
  5. Calculate economics using profitabilityService.offerEconomics (recipe costs, margins)
  6. Calculate inventory impact via InventoryDemandService
  7. Calculate cannibalization: incremental = total_expected - baseline
  8. Cannibalization_risk = incremental / total_expected (flag if < 0.5)
  9. Apply constraints (see Task 4)
- Return sorted by objective (default: profit_growth = expected_contribution)

**acceptance_criteria:**
- `grep -q "compareScenarios" backend/src/services/scenarioEngine.ts`

- `grep -q "cannibalization" backend/src/services/scenarioEngine.ts`

### Task 4: Create ConstraintValidator
**read_first:**
- backend/src/models/Settings.ts (restaurant settings)
- backend/src/modules/promotions/services/promotionsService.ts (offer validation)

**action:**
Create `backend/src/services/constraintValidator.ts`:
- `ConstraintValidator` class with method `validate(scenario, restaurantSettings): ConstraintResult`
- Hard constraints (CONTEXT.md D-26 to D-31):
  - min_margin: scenario.expected_contribution_margin >= settings.min_margin (default 15%)
  - max_discount: scenario.offer_config.value <= settings.max_discount (default 30%)
  - min_price: scenario.effective_price >= ingredient_cost * (1 + min_margin)
  - inventory: scenario.required_stock <= current_stock * 0.8 (safety buffer)
  - eligibility: offer.valid_for_segments, offer.time_windows, offer.product_constraints
  - duration: offer.duration <= settings.max_promotion_duration
  - custom_rules: restaurant-configured rules from Settings
- Return { valid: boolean, violations: string[] }

### Task 5: Create OptimizationService (Bounded Search)
**read_first:**
- backend/src/services/scenarioEngine.ts
- backend/src/services/constraintValidator.ts
- backend/src/services/elasticityService.ts

**action:**
Create `backend/src/services/optimizationService.ts`:
- `OptimizationService` class with method `findOptimalDiscount(restaurantId, branchId, productId, objective): Promise<OptimizationResult>`
- Discount levels: [0, 10, 20, 30, 40, 50] (INR, not %)
- For each discount level:
  1. Create promo scenario with that discount
  2. Get elasticity for product at that discount
  3. Run scenario engine
  4. Validate constraints
  5. Score by objective:
     - revenue_growth: expected_revenue
     - profit_growth: expected_contribution
     - aov_growth: expected_aov (from combo/addon logic)
     - footfall_growth: expected_orders (demand / avg_items_per_order)
     - inventory_reduction: -predicted_ending_stock (minimize)
     - customer_retention: estimated_repeat_orders (from segment targeting)
     - slow_hour_utilization: demand_in_slow_hours / total_demand
- Return best valid discount with full scenario details
- If no valid discount: return "no_promo" scenario with explanation

**acceptance_criteria:**
