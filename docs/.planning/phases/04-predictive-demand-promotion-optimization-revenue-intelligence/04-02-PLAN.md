# Phase 4.2: Inventory Demand Prediction & Stockout Risk

## Objective
Connect demand forecasts to ingredient-level consumption and stockout risk. Integrate with existing inventory/reorder system.

## Must-Haves (Goal-Backward Verification)
- [ ] Forecast → Recipe → Ingredient quantities pipeline using existing Recipe model and costIntelligenceService
- [ ] Stockout risk = predicted_consumption > current_stock × 0.8 (reuse surplus threshold)
- [ ] Integration with existing inventory/reorder system (extend Purchase suggestions)
- [ ] Stockout warnings surfaced in Advisor dashboard as "Protect Friday Stock" action cards

## Tasks

**read_first:**
- backend/src/models/index.ts
- backend/src/models/InventoryEvent.ts
- backend/src/models/Recipe.ts

**action:**
Create `backend/src/models/StockoutRisk.ts`:

### Task 2: Create InventoryDemandService
**read_first:**
- backend/src/services/forecastService.ts (ForecastEngine output)
- backend/src/modules/recipes/services/costIntelligenceService.ts (recipe ingredient mapping)
- backend/src/models/Recipe.ts
- backend/src/models/Product.ts

**action:**
Create `backend/src/services/inventoryDemandService.ts`:
- `InventoryDemandService` class with method `predictIngredientConsumption(restaurantId, branchId, horizonDays): Promise<IngredientConsumption[]>`
- Pipeline:
  1. Get forecasts for products/variants (from ForecastEngine)
  2. For each forecasted product, get active Recipe (Recipe.status === 'active')
  3. For each RecipeComponent, calculate: ingredient_quantity = forecasted_demand * component.quantity * (1 + component.wastagePercent/100)
  4. Aggregate by ingredient_id across all products
  5. Get current stock from Product.currentStock (for ingredients tracked as products) or InventoryEvent aggregation
  6. Calculate risk_level: CRITICAL if predicted > current, HIGH if predicted > current*0.8, MEDIUM if > current*0.6, LOW if > current*0.4, NONE otherwise
  7. Calculate time_to_stockout_hours = (current_stock - safety_stock) / (predicted_consumption / (horizonDays * 24))
- Reuse surplus threshold (80%) from `deriveSurplusItems` in recommendationContext.ts

**acceptance_criteria:**
- `grep -q "predictIngredientConsumption" backend/src/services/inventoryDemandService.ts`
- `grep -q "RecipeComponent" backend/src/services/inventoryDemandService.ts`
- `grep -q "wastagePercent" backend/src/services/inventoryDemandService.ts`
- `grep -q "risk_level" backend/src/services/inventoryDemandService.ts`
